一片草地的诞生：从绿色底板到风与云影

一片看起来很复杂的像素草地，可以拆成一组能单独理解的机制。点击上方阶段按钮逐步叠加效果，拖动画面检查不同视角，再用「对比上一步」看清这次究竟新增了什么。

拆解笔记 / STEP 1

底板：先约定世界与像素的尺度

本步新增：绿色平面、正交相机、低分辨率画面。 暂时没有草、噪声或动态光照。能看到的厚边是为了方便观察平面边界而增加的展示底座，不参与草地算法。

地面位于世界坐标的 XZ 平面，Y 轴向上，大小是 12 × 12。相机围绕场景中心旋转，正交投影保证远处的草不会因距离变小。原项目也是正交相机，但原场景没有这里的鼠标环绕交互。

像素化发生在输出阶段。 我们先渲染 640 × 360 的图像，再由 CSS 的 image-rendering: pixelated 放大。它不会把三维坐标变成整数，也没有实现相机像素吸附。因此缓慢转动时，细边缘仍可能出现像素跳动。

地面片元目前只输出统一绿色。后续阶段会在同一个函数里逐步启用色块和光照，而不是替换整个场景。

贴图组合：无。 这一步的底色来自代码中的 RGB 常量。试着关闭「像素化」，观察几何体完全相同，改变的只是画面分辨率。

拆解笔记 / STEP 2

草片：透明轮廓与面向相机的平面

本步新增：大量草片、透明度裁切和少量装饰变体。 每撮草不是一个完整的叶片模型，而是一张竖起的矩形。贴图的 alpha 通道决定哪些像素留下，透明部分直接丢弃。

grassleaf.png 是普通草的形状，accentleaf.png 是另一种点缀轮廓。棋盘格表示透明背景，不会画进三维场景。两张图来自 Dylearn，未修改原文件，采用最近邻采样，避免像素轮廓被插值模糊。

不是每撮草都单独提交一次绘制。 所有草共用一个四边形，用实例属性传入位置、随机数和尺寸。固定种子保证切换阶段或刷新后，布局仍能重复观察。默认显示 18,000 撮，可用草量滑杆调整。

为了让贴图不随着观察方向变成一条细线，使用相机的右向量和上向量构建草片。下方代码中的局部摇摆要到第四步才启用。这个网页版本把草片的底边设为旋转支点，以便直观观察草根不移动；这是教学实现的调整。

渲染时，普通草和装饰草使用同一个材质。固定随机数中约 4.5% 选择浅色草、1.5% 选择另一张草叶贴图；比例高于原 Demo，便于在小画面里看清点缀。leaf.rgb 保留贴图的明暗，leaf.a 控制轮廓。

贴图组合：草叶 RGB × 基础颜色；草叶 alpha → 裁切。 此时没有噪声。旋转视角时观察叶片始终朝向相机，再调低草量，看看一撮草究竟是什么形状。

拆解笔记 / STEP 3

色块：让草与地面说同一种颜色语言

本步新增：两张世界坐标噪声和三种绿色。 色块草并不是另外一套几何体，而是同一套草片在不同区域取得不同颜色。

输入 本步如何使用 与其他输入的关系
patch-a，种子 17 以 worldXZ × 0.12 采样，超过 0.52 时使用浅绿 覆盖基础绿色
patch-b，种子 83 以 worldXZ × 0.10 采样，超过 0.57 时使用深绿 在重叠区域继续覆盖 A
草叶贴图 保留草的轮廓与纹理明暗 不决定区域分布

关键区别在采样位置。 地面使用每个片元的世界位置，因此能画出连续色块；草使用每撮草的根部位置，因此整撮草选中同一个区域颜色。不能把噪声绑在屏幕坐标上，否则旋转相机时，色块就会在地上滑动。

这里的色块边界是阈值产生的硬边界。大量带草叶轮廓的草片覆盖边缘后，平滑平面的色块看起来会长出参差细节；源码没有另加一个通用的边缘模糊滤镜。装饰草会在区域色之后使用自己的点缀颜色。

这些噪声到底是什么？ 原项目用 Godot 的 FastNoiseLite 资源；网页演示改用下面的周期 value noise，组合四个不同频率的层。它们不是同一个噪声算法，所以具体斑块不会与原项目逐像素一致。上方预览显示的就是上传给 GPU 的数据，而非示意图片。

纹理以 Repeat 模式循环、线性过滤采样。周期网格让纹理首尾衔接，固定种子让图案稳定。选择「色块噪声」可检查 A 层灰度；切回最终画面，观察灰度阈值如何变成浅绿色区域。

拆解笔记 / STEP 4

风动：把一张移动的噪声变成一片草浪

本步新增：局部摇摆 + 世界风场旋转。 局部摇摆让各撮草轻微左右摆动，世界风场让一片区域的草协同倾斜。

wind 使用独立种子 41，不复用色块噪声。色块是固定的地貌分布，风是随时间移动的场；如果两者绑定，草的运动会过度依赖颜色边界。

同一张风纹理采样两次。 两层沿主风向左右各偏转 10°，第二层还改变空间尺度与移动速度。两次采样相乘，加上偏置，映射到 -1～1 的旋转强度。这里与原算法保持相同的组合思路，噪声纹理与部分尺寸参数做了网页演示适配。

根据风向构造垂直于它的旋转轴，再用 Rodrigues 旋转公式旋转草片偏移。世界风向固定为 XZ 平面内的 (0.6, 1.0)；相机转了，风向也不会跟着变成另一个世界方向。

局部摇摆则是一个带随机相位的正弦，围绕相机朝向的轴摆动，代码在第二步的 billboard 段内。它与世界风动叠加，但不负责制造大面积的草浪。

组合顺序：局部摆动 → 角色拨草（第七步才启用）→ 世界风动 → 相机投影。 旋转顺序不可随意交换，因为绕不同轴的旋转一般不满足交换律。选择「风场噪声」，观察明暗团块与倾斜区域的关系；把风速设为 0 会停止风纹理流动，但局部正弦摇摆仍会继续。

拆解笔记 / STEP 5

假透视：用 UV 变形补充倾倒的体积感

本步新增：随高度变化的贴图横向缩放。 这是原实现里与“折叠感”最接近的部分，不是沿四边形对角线折叠网格，也没有增加叶片骨骼。

先把横向 UV 中心移到 0，再根据草叶高度、风强度以及相机与风向的夹角调整宽度，最后移回 0.5。这样叶片上部会比下部更明显地收缩或展开。

贴图组合：风噪声 → 横向 UV 变形 → 采样草叶贴图。 这一步没有新增纹理，只改变同一张草叶图的读取位置。色块仍由根部世界坐标决定，不使用变形后的草叶 UV。

网页网格的 UV.y = 1 位于草尖，和原 Godot shader 所使用的方向不同，因此高度因子做了对应转换。越出横向边界的片元被丢弃，避免纹理另一侧重复出现。

开启「对比上一步」，缓慢拖动相机，从顺风方向转到侧风方向观察：风向与视线越接近，假透视影响越明显。这个变化比较细，建议暂停后放大观察；它不应把叶片变成夸张的橡皮片。

拆解笔记 / STEP 6

分帧：让草像手绘动画一样更新姿态

本步新增：草的时间量化和随机更新相位。 默认每秒约 5 次草姿态更新，浏览器仍然正常绘制，相机拖动也不受这个更新频率限制。

每撮草用实例随机数得到 phase，再把时间舍入到 1 / uFps 的间隔。风场和局部正弦使用量化后的时间，所以它们一起产生分帧感。不同草的更新时间稍微错开，避免所有叶片在同一瞬间跳动。

贴图组合没有增加：仍然是上一阶段的风纹理与草叶贴图。 改变的是采样噪声时使用的时间，而不是把噪声图片转成动画帧。

调节草的帧率到 2、5、15，对比更新节奏；再开启「对比上一步」查看连续运动。原项目用位置生成相位，这里改用固定实例随机数，让分布更容易复现。后面加入的角色运动与云影使用连续时间，不受这个参数控制。

拆解笔记 / STEP 7

角色拨草：用距离场把草向外推开

本步新增：深色球体角色、距离衰减和两个方向的拨草旋转。 球体只用于展示交互，不是原项目的人物或 Logo。它沿固定路径运动，便于反复比较。

草根到角色的距离除以作用半径，得到归一化距离；半径外影响为零，越靠近中心影响越强。向量方向分别投影到相机的横向和地面上的前后方向，再转换成左右与前后两个旋转。

代码对零距离、半径和幂函数输入做了保护，避免中心点归一化或负数小数次幂产生无效值。拨草之后继续叠加原有风动，vPushForward 还会传到第五步的 UV 假透视中，使前后倾倒具有相应的形状变化。

贴图组合：沿用草叶、底色色块、风场；角色影响由坐标计算，不新增交互贴图。 原项目支持一个角色位置数组，并用脚本约 10 Hz 传递位置；本网页演示使用一个角色，位置每帧传入，便于聚焦算法。

调大「拨草范围」观察影响区域。这不是物理模拟：角色离开后，当前位置影响归零，草回到风动决定的姿态；没有持续的踩踏印记，也没有弹簧回弹状态。

拆解笔记 / STEP 8

卡通光照：把连续亮度组织成有限色阶

本步新增：方向光、有限明暗色阶和草片的窄范围过渡。 第三步解决“物体本身是什么颜色”，这一步解决“它受到多少光”。两者不能混成同一种色块处理。

核心先计算法线与光方向的点积，再量化到有限亮度级别。地面保持硬分界；草片在每个级别的边界附近用 smoothstep 留出一小段过渡，这对应原项目的 Hybrid Toon Shading 思路。

贴图组合：第三步得到的底色 × 本步计算的光照强度。 此时没有新增光照贴图，也还没有云影。叶片透明轮廓继续生效。

原项目用 LIGHT_VERTEX = model_origin 统一一撮草的光照位置。网页版本同样把根部传给光照函数；但没有复刻 Godot 的完整灯光、阴影与法线管线，而是使用向上的基础法线，随风动轻微倾斜，并增加少量环境亮度。这些调整让算法在独立浏览器示例中更容易观察，不应理解成与原画面严格一致。

调节「光照色阶」，注意颜色数量变化。静止的平坦地面法线一致，所以在这一阶段可能整块地面明暗接近；下一步云影加入后，同一地面上会出现空间变化的明暗区域。

拆解笔记 / STEP 9

云影：把移动的天空映射到世界

本步新增：假想云层高度、云噪声投影与动态光照遮罩。 并不绘制三维云朵，而是计算“这块地面对应云层的哪里”，再采样那里有多少遮挡。

沿光照方向，从草根或地面位置求出与云层平面的交点。再用交点 XZ 坐标读取两层移动云噪声：两层方向略有分离，尺度和速度也不相同。乘积经阈值、对比度和最小亮度处理后，得到光照上限。

第八步的 shadeGrass() 使用 min(diffuse, cloudAt(root)) 让云影限制直射光，再执行色阶处理。因此阴影也进入了卡通明暗系统，而不是在最终画面上叠一张半透明黑图。

纹理 坐标与时间 最终控制什么
grassleaf / accentleaf 草片 UV，经过假透视变形 叶片轮廓与局部纹理明暗
patch-a / patch-b 固定世界 XZ 坐标 地面和草的区域颜色
wind 草根世界 XZ + 分帧时间偏移 旋转角度与假透视强度
cloud 投影到云层的世界坐标 + 连续时间偏移 地面和草的光照上限

四种空间关系，最后汇成一个画面： 世界坐标让颜色和风场附着在场景里；草叶 UV 保持叶片轮廓；相机基向量维持草片朝向；光照方向将云层投影到地面。

选择「云影遮罩」单独观察明暗场，再切回最终画面。将风速设为 0、保持云速，区分“叶片运动”和“光照运动”；将云速设为 0，则云影停在原处。暂停按钮会同时冻结草、角色与云的时间，但仍能拖动相机检查它们的空间关系。

这就是最终组合。它没有加入人物描边、后处理法线描边或永久踩踏痕迹，这些不属于本篇九个阶段的实现范围。
